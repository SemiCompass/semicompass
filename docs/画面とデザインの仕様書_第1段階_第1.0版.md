## 3. デザインの原則

1. **内容が主役**：飾りで目を引かない。表、グラフ、出典、見出しと段落で、情報の構造をそのまま見せる（DS-01、DS-09）。
2. **白書と辞典の紙面**：白に近い背景、深い青緑の文字の差し色、1pxの罫線、十分な余白。強調は太字と琥珀色の印だけで行う。
3. **少ない値を、何度も使う**：文字の大きさは7段階、余白は8段階、色は、基本の色14、状態の色4、グラフの色9に限る。同じ役割には、どのページでも同じ値を使う。
4. **数字を読ませる**：数値は等幅の数字（桁がそろう数字）で右に揃え、単位、期、出典を必ず添える（DS-02）。
5. **誰でも使える**：JIS X 8341-3のレベルAA（DS-03）。色だけで区別しない。キーボードだけで操作できる。
6. **動かさない**：動きは、開閉など操作の結果だけにする。端末の「視差効果を減らす」の設定では、動きを止める。

## 4. 色

### 4.1 基本の色
文字と背景のコントラスト比は、背景`--color-bg`（#FBFAF6）に対する値である。本文の文字は4.5以上、大きな文字と図形は3以上を守る（DS-03）。

| 変数 | 値 | 用途 | コントラスト比 |
| :--- | :--- | :--- | ---: |
| `--color-bg` | #FBFAF6 | ページの背景（わずかに温かい白） | — |
| `--color-surface` | #FFFFFF | 表、注記、入力欄の背景 | — |
| `--color-surface-sunken` | #F2F4F2 | 表の見出し行、コードの背景、ヘッダーの帯 | — |
| `--color-text` | #1B2A2C | 本文、見出し | 14.2 |
| `--color-text-muted` | #4A5B5E | 補足、日付、出典の文字 | 6.8 |
| `--color-primary` | #0B4F54 | 深い青緑。リンク、ロゴ、現在の場所の文字、1系列のグラフ | 8.9 |
| `--color-primary-hover` | #083B3F | リンクにポインターを重ねたとき、押したとき | 11.8 |
| `--color-primary-tint` | #E8F1F0 | 選んでいる項目の背景、「この会社のポイント」の背景 | — |
| `--color-visited` | #3D5F61 | 訪問済みのリンク（紫は使わない） | 6.7 |
| `--color-accent` | #B7791F | 琥珀色。要点と現在地の印（左の太い線、目次の現在地の印）。**文字には使わない** | 3.5（図形） |
| `--color-accent-text` | #8A5A12 | 琥珀色を文字に使う必要があるとき | 5.7 |
| `--color-border` | #C9D3D3 | 区切りの罫線（飾りの線） | — |
| `--color-border-strong` | #6B7C7E | 入力欄の枠、操作できる部品の境界（3以上が要る線） | 4.2 |
| `--color-focus` | #0B4F54 | キーボードで選んだときの枠 | 8.9 |

* 白い文字を`--color-primary`の上に置くときのコントラスト比は9.3である（ボタン）。
* 文字に`--color-accent`を使わない（コントラストが足りない）。

### 4.2 状態の色（予約）
状態の色は、状態の表示（DS-06）と注記だけに使い、グラフの系列には使わない。必ず記号と言葉を添え、色だけで伝えない。

| 変数 | 値 | 用途 |
| :--- | :--- | :--- |
| `--color-warning-bg` | #FFF4E0 | 注意（未反映の表示、確認中の表示）の背景。枠の左の線は`--color-accent` |
| `--color-error` | #B42318 | 誤りの文字と枠（コントラスト比6.3） |
| `--color-error-bg` | #FDECEA | 誤りの背景 |
| `--color-success` | #1E6B3A | 完了の文字（コントラスト比6.3） |

### 4.3 グラフの色
グラフの色は、基本の色（4.1）とは別に用意する（DS-02）。色覚の多様性への配慮は、計算で確かめた（2026年10月6日、色の検査のスクリプトで、背景#FBFAF6に対し、明るさの範囲、彩度、色覚の違いの見え方での色の差、通常の見え方での色の差、背景とのコントラストを、すべての組み合わせで確認した。`--chart-cat-4`だけがコントラスト3未満の警告）。

| 変数 | 値 | 用途 |
| :--- | :--- | :--- |
| `--chart-single` | #0B4F54 | 1系列のグラフ（売上高の推移など）。凡例は置かない |
| `--chart-highlight` | #0B4F54 | 半導体関連のセグメント |
| `--chart-other` | #9AA7A8 | 半導体関連以外、「その他」。斜線の模様を重ねる |
| `--chart-cat-1` | #008C7A | 複数系列の1番目（緑青） |
| `--chart-cat-2` | #C2550A | 2番目（朱） |
| `--chart-cat-3` | #4A7BD0 | 3番目（青） |
| `--chart-cat-4` | #C2A000 | 4番目（黄土）。背景とのコントラストが3未満のため、使うときは数値のラベルか表を必ず添える |
| `--chart-grid` | #E3E8E8 | 目盛りの線 |
| `--chart-axis` | #6B7C7E | 軸の線 |

* 系列の色は、決まった順で割り当て、絞り込みで系列が減っても、残った系列の色を変えない。
* 5系列を超えるときは、色を足さずに「その他」にまとめるか、グラフを分ける。
* 企業やセグメントの色の割り当ては、`config/chart-colors.yaml`（データ定義書7.10）で持ち、サイト全体で同じにする。

## 5. 文字と文字組み

### 5.1 書体
端末の文字を使う（1.3）。和文はゴシック体だけとし、明朝体は使わない。

```css
--font-family-base: system-ui, -apple-system, "Hiragino Sans", "Hiragino Kaku Gothic ProN",
  "Yu Gothic UI", "Yu Gothic", "Noto Sans JP", Meiryo, sans-serif;
--font-family-mono: ui-monospace, "SFMono-Regular", Menlo, Consolas, "Noto Sans Mono", monospace;
```

* 斜体は使わない（和文に斜体の字形がない）。
* 太さは、標準（400）と太字（700）の2つだけとする。

### 5.2 文字の段階
大きさは`rem`（端末の文字の大きさの設定に従う単位）で指定する。1remは16pxを基準とする（UI-08）。

| 名前 | 変数 | 大きさ | 行間 | 字間 | 太さ | 用途 |
| :--- | :--- | ---: | ---: | ---: | :--- | :--- |
| 大見出し | `--text-h1` | 2rem（32px）。スマートフォンは1.75rem（28px） | 1.4 | 0.01em | 700 | ページの大見出し（1ページに1つ） |
| 中見出し | `--text-h2` | 1.5rem（24px） | 1.5 | 0.01em | 700 | 本文の`##` |
| 小見出し | `--text-h3` | 1.25rem（20px） | 1.5 | 0.02em | 700 | 本文の`###`、部品の見出し |
| 導入 | `--text-lead` | 1.125rem（18px） | 1.8 | 0.02em | 400 | トップのサイトの説明、この会社のポイント |
| 本文 | `--text-body` | 1.0625rem（17px） | 1.85 | 0.02em | 400 | 本文の段落、箇条書き |
| 表・部品 | `--text-dense` | 0.9375rem（15px） | 1.5 | 0 | 400／700 | 表、グラフの注記、メニュー、ボタン |
| 注記 | `--text-small` | 0.875rem（14px） | 1.6 | 0.02em | 400 | 出典、日付、フッター。14pxより小さい文字は使わない |

* 本文の1行は、全角で約35〜45字に収める。本文の最大幅は`--content-max-width: 40rem`（17pxの文字で約37字）とする。
* 段落の間は`--space-5`（1.5rem）空ける。字下げはしない。
* 見出しの上の余白は、下の余白の2倍以上にして、見出しが後ろの段落に属して見えるようにする（`##`は上`--space-7`、下`--space-4`）。

### 5.3 文字組みの規則
* **見出しと導入の折り返し**：見出しと導入の文字（`--text-lead`）は、単語や文節の途中で折り返さない。`word-break: auto-phrase`（対応する閲覧ソフトで文節の切れ目で折り返す）と`text-wrap: balance`（行の長さをそろえる）を付ける。対応しない閲覧ソフトでは、普通に折り返す。
* **約物の詰め**：見出し、ボタン、表の見出しには`font-feature-settings: "palt"`（括弧や句読点の空きを詰める）を付ける。本文には付けない（読みやすさを優先する）。
* **数字**：表、主要な数値、グラフの目盛りには`font-variant-numeric: tabular-nums`（桁がそろう数字）を付ける。表の数値は右に揃える。
* **単位**：表では、単位を列の見出しに書き（「売上高（億円）」）、各セルには数字だけを書く。文章では、数字と単位を続けて書く（「8,325.5億円」）。
* **長い語**：URLや英語の長い名前は、枠からはみ出す場合だけ折り返す（`overflow-wrap: anywhere`）。
* **強調**：太字（700）だけを使う。下線はリンクだけに使う。文字の色を変えて強調しない。
* **文の調子**：記事の本文（`content/`のMarkdown）は、である調とする（CLAUDE.md 5.1）。画面の案内の文（404のページ、状態の表示、注記・未反映などの表示、ボタン、入力の誤り、仮のページの注記）は、です・ます調とする（2026年10月6日、運営者）。

## 6. 余白、格子、画面の幅

### 6.1 余白の段階
余白は4pxを基にした8段階だけを使う。

| 変数 | 値 | 主な用途 |
| :--- | ---: | :--- |
| `--space-1` | 0.25rem（4px） | 記号と文字の間 |
| `--space-2` | 0.5rem（8px） | タグの内側、表のセルの上下 |
| `--space-3` | 0.75rem（12px） | 表のセルの左右、ボタンの上下 |
| `--space-4` | 1rem（16px） | ページの左右の余白（スマートフォン）、見出しの下 |
| `--space-5` | 1.5rem（24px） | 段落の間、部品の内側 |
| `--space-6` | 2rem（32px） | 部品と部品の間、ページの左右の余白（タブレット以上） |
| `--space-7` | 3rem（48px） | 中見出しの上、本文の列と右の列の間 |
| `--space-8` | 4rem（64px） | ページの大きな区切り（本文とフッターの間） |

### 6.2 画面の幅（要件定義書3.5の値を確定する）

| 区分 | 画面の幅 | 変数 | 構成 |
| :--- | :--- | :--- | :--- |
| スマートフォン | 767px以下 | — | 1列。左右の余白は`--space-4` |
| タブレット | 768〜1023px | `--bp-tablet: 768px` | 1列。左右の余白は`--space-6` |
| PC | 1024px以上 | `--bp-pc: 1024px` | 本文（最大40rem）と右の列（16rem）の2列。列の間は`--space-7` |

* ページの外枠の最大幅は`--layout-max-width: 68rem`（1088px）とし、中央に置く。
* PCで2列にするページ（企業ページ、工程ページ、用語ページ、ニュースの個別）は、本文の左端を、ヘッダーのロゴの左端とそろえる。
* 右の列を持たないページ（トップ、一覧、検索）は、外枠の幅いっぱいを使う。ただし、文章の段落は`--content-max-width`を超えない。

### 6.3 格子
* すべての要素の左端を、外枠の左端（ページの左右の余白の内側）か、本文の列の左端にそろえる。
* 表やグラフは本文の列の幅いっぱいに置く。PCで幅が足りない表は、本文の列と右の列を合わせた幅まで広げてよい（その場合、右の列の目次は表の上で止める）。
* 要素の間隔は、関係の近いものを`--space-2`〜`--space-4`、別のまとまりを`--space-6`以上とし、余白でまとまりを示す。

## 7. 罫線、角、図と記号

| 変数 | 値 | 用途 |
| :--- | :--- | :--- |
| `--border-width` | 1px | 区切り、表、部品の枠 |
| `--border-width-accent` | 4px | 要点の印（左の太い線） |
| `--border-width-focus` | 3px | フォーカスの枠 |
| `--focus-offset` | 2px | フォーカスの枠と要素の間 |
| `--radius-control` | 2px | ボタン、入力欄、タグ |
| `--radius-none` | 0 | それ以外（表、注記、部品の枠） |

* 影、グラデーション、半透明のぼかしは使わない（運用ルール書10.3.3）。重なりは罫線と背景の色で示す。
* 図と記号は、意味のあるもの（外部リンクの印、開閉の印、並べ替えの印、警告の印）だけを使い、線の太さは1.5pxにそろえる。SVGで作り、文字と同じ色にする。装飾だけのアイコンは使わない。
* ロゴは、方位磁針の針と半導体のチップを組み合わせた簡素な図形とし（DS-01）、SVGで作る（14章の未決事項2）。

## 8. 共通の部品

部品は`src/components/`に1つずつ作り、ページごとに作らない（DS-04）。部品の一覧のページ（プレビューだけで出す）で、すべての状態を並べて確かめる。

### 8.1 ヘッダー
* 高さ：スマートフォン56px、タブレット以上64px。下に`--border-width`の罫線。背景は`--color-surface`。
* 左にロゴとサイト名、右に検索欄と主要メニュー（企業、工程、ニュース。`config/menu.yaml`の順）。
* スマートフォン：主要メニューは「メニュー」のボタンで開閉する（ボタンは記号と「メニュー」の文字）。検索欄はヘッダーの2段目に常に出す。ヘッダー全体は画面に張り付けない（画面の高さの4分の1の制限、要件定義書3.5）。
* 現在のページが属するメニューの項目は、下に`--color-accent`の3pxの線を引き、`aria-current`を付ける。

### 8.2 パンくずリスト
* 大見出しの上に置く。`--text-small`、`--color-text-muted`。区切りは「›」の記号。最後の項目（現在のページ）はリンクにしない。
* スマートフォンで長いときは、1行のまま横にスクロールせず、折り返す。

### 8.3 ページの頭（大見出しと日付）
* 大見出しの下に、公開日・更新日・作成者を`--text-small`で1行に並べる（SE-03）。
* AIが書いた本文を含むページは、日付の行に「AI作成」の表示（8.9）を置く。

### 8.4 ページ内の目次
* PC：右の列に置き、スクロールしても見える位置に張り付ける（`position: sticky`）。現在読んでいる見出しの項目に、左の`--border-width-accent`の琥珀色の線を付ける。
* スマートフォンとタブレット：大見出しの後に、開閉できる「このページの目次」として置く（初めは閉じる）。
* 項目は中見出し（`##`）だけとする。

### 8.5 リンクとボタン
* 本文のリンク：`--color-primary`、下線あり（下線の位置は文字から0.2em下げる）。訪問済みは`--color-visited`。外部のサイトへのリンクは、後ろに外部リンクの記号と、読み上げ用の「（外部サイト）」を付ける。
* 主ボタン：背景`--color-primary`、白い文字、`--radius-control`、高さ44px以上、左右の余白`--space-5`。1つの画面に1つまで。
* 副ボタン：背景`--color-surface`、枠`--color-border-strong`、文字`--color-primary`。
* ポインターを重ねたときは、色を`--color-primary-hover`にする。動きは付けない。

### 8.6 検索欄
* 入力欄：高さ44px、枠`--color-border-strong`、`--radius-control`、背景`--color-surface`。左に虫めがねの記号、入力の例を「企業名・証券コード・用語」と表示する。
* 候補（FR-701）は入力欄の直下に一覧で出し、上下の矢印のキーで選べるようにする。候補の各行は、名前（太字）と種類（企業・工程・用語）と、企業なら証券コードを1行で示す。

### 8.7 表
* 枠は上下の罫線だけとし、縦の罫線は使わない。見出し行の背景は`--color-surface-sunken`、見出し行の下は`--color-border-strong`の罫線。
* 行の高さ：上下`--space-2`、左右`--space-3`。文字は`--text-dense`。
* 数値の列は右揃え、等幅の数字。文字の列は左揃え。
* 列の見出しに単位を書く。表の下に、出典と時点を`--text-small`で書く（8.10）。
* 幅が足りないときは、表を囲む枠の中だけで横にスクロールさせ、最初の列（企業名など）を左に固定する。スクロールできることを、枠の右端の罫線と「横にスクロールできます」の注記で示す。
* 並べ替えができる列（企業一覧）は、見出しに並べ替えの記号を付け、`aria-sort`で状態を示す。

### 8.8 この会社のポイント（主要な数値の枠）
* 背景`--color-primary-tint`、左に`--border-width-accent`の`--color-primary`の線、内側の余白`--space-5`。
* 1行目に一言での説明（`--text-lead`）。その下に主要な数値を、ラベル（`--text-small`）と数値（`--text-h3`の大きさ、等幅の数字）の組で横に並べる（スマートフォンは2列）。
* 数値の下に、期（「2026年3月期」）と出典を`--text-small`で書く。
* 同じ形の枠を何個も並べない（この枠は企業ページに1つだけ）。

### 8.9 注記、AI作成の表示、未反映の表示、警告
| 種類 | 見た目 | 文言 |
| :--- | :--- | :--- |
| 注記 | 背景`--color-surface`、枠`--color-border`、左に`--color-border-strong`の4pxの線 | 会計基準の切り替え、数値の注意など |
| AI作成の表示 | `--text-small`、記号＋「AIが下書きし、運営者が確認しました」。説明のページ（`/editorial-policy/`）へのリンク | UI-06 |

### 8.10 出典
* 本文の`[S1]`は、上付きの小さな番号のリンク（`[1]`の形）にし、ページの下の出典の一覧の該当行へ移動できるようにする。
* 出典の一覧：番号、資料の名前、発行元、公表日、確認日、該当のページを1行ずつ、`--text-small`で並べる。EDINETの資料は、公共データ利用規約の出典の表示を部品で自動で付ける（LG-04）。
* グラフと表の下の出典は「出典：有価証券報告書（2026年3月期）、EDINET。2026年10月6日確認」の形で1行にまとめる。

### 8.11 タグ
* 工程、分類、企業のタグ：背景`--color-surface`、枠`--color-border`、`--radius-control`、`--text-dense`、高さ32px（タッチの画面では押せる範囲を44px以上に広げる）。
* タグはリンクとし、色で種類を分けない（種類は前に「工程：」などの文字で示す）。

### 8.12 状態の表示（DS-06）
| 状態 | 表示 |
| :--- | :--- |
| 読み込み中 | 本文の位置に「読み込んでいます」の文字だけを出す。回る印は使わない（静的なサイトのため、ほぼ検索の候補だけ） |
| データがない | 枠`--color-border`の中に、何がないかと、代わりの行き先（例：「この期のセグメント情報は開示されていません。全社の業績を見る」） |

* Coming Soon：大見出しの下に、注記の見た目で「このページは準備中です。公開範囲と今後の予定」とリンクを置く。

## 9. ページの型

ここでは、各ページの並びと、幅ごとの変化を定める。内容の順は要件定義書3.2〜3.4に従う。

### 9.1 トップページ（`/`）
1. サイト名とロゴ、説明の一文（`--text-h1`）。
2. サイトの説明（`--text-lead`、最大`--content-max-width`）。
3. 3つの入口：「工程から探す」「ニュース・テーマから探す」「企業名・証券コードで探す」。**同じ形のカードを3つ並べない**。PCでは3列の定義の一覧（見出し、一文の説明、リンクの一覧）、スマートフォンでは縦に並べる。「工程から探す」には、前工程・後工程などの工程の名前をそのままリンクとして並べ、「企業名・証券コードで探す」には検索欄を置く。
4. 新着のニュース解説：日付、見出し、関係する企業のタグの一覧（最大5件）。
* 最初の画面（幅360px、高さ約640px）に、1〜3が収まることを確かめる（UI-16）。

### 9.2 企業ページ（`/companies/{slug}/`、詳細掲載）
* PC：本文の列と右の列（目次）。スマートフォン：1列、目次は開閉式。
* 並び（要件定義書3.4）：見出し（企業名、証券コード、企業区分、工程のタグ）→この会社のポイント（8.8）→目次→事業概要・工程上の位置づけ→業績（グラフと表）→IR重要ポイント→働く環境→ニュース→資料→出典・関連。
* 業績は、グラフ（10章）の直後に、同じ数値の表を「表で見る」の開閉で置く。
* セグメントのグラフでは、半導体関連のセグメントを`--chart-highlight`、それ以外を`--chart-other`で示し、凡例と数値のラベルを付ける。

### 9.3 企業一覧（`/companies/`）
* 表（8.7）で並べる。列：企業名（略称、リンク）、証券コード、企業区分、工程、売上高（億円、最新の通期）、半導体関連の比率、掲載の状態（詳細／準備中）。
* 表の上に、工程と企業区分の絞り込み（選ぶ欄を1行に並べる）と、件数の表示を置く。
* カードの格子にしない。

### 9.4 工程ページ（`/processes/{slug}/`）
* 用語ページと同じ2列の構成。並び：見出し→この工程の要点（2〜3行）→解説（`##`の見出し）→この工程の企業（表）→関係する用語→出典。
* 工程の前後のつながりは、前の工程・次の工程へのリンクを本文の最後に置く。

### 9.5 用語ページ（`/glossary/{slug}/`）、用語集
* 用語ページ：見出し（用語、読み）→短い定義（`--text-lead`、200字以内）→解説→関係する工程と企業→出典。
* 用語集：五十音とアルファベットの見出しで区切った一覧（用語、読み、短い定義の1行目）。

### 9.6 ニュース一覧・個別
* 一覧：日付、見出し、分類、関係する企業のタグを1件ずつ罫線で区切って並べる。
* 個別：2列の構成。見出し→日付と分類→元記事（見出し、発信元、リンク）→3つの中見出しの解説（FR-402）→関係する企業・工程→出典。

### 9.7 検索の結果（`/search/`）
* 検索欄を上に置き、結果を種類（企業、工程、用語、ニュース）ごとの見出しで分けて並べる。結果がないときは、データがない状態の表示（8.12）と、入力の例を示す。

## 10. グラフ

### 10.1 形の選び方
| 内容 | 形 |
| :--- | :--- |
| 売上高・利益の推移 | 縦の棒（期ごと）。1系列なら`--chart-single` |
| セグメント別の売上の推移 | 積み上げの縦の棒。半導体関連を下に置き、`--chart-highlight`と`--chart-other`で示す |
| 地域別の売上（1期） | 横の棒（大きい順）。円グラフは使わない |
| 従業員数・平均年間給与の推移 | 折れ線（2本以上なら凡例と線の種類を変える） |
| 1つの数字 | グラフにせず、数値の表示（8.8）にする |

* 2つの縦軸を持つグラフは作らない。単位の違う数値は、グラフを分ける。

### 10.2 形の細部
* 棒の幅は、棒と棒の間の1.5倍。積み上げの部分の間は、背景の色の2pxの隙間。
* 折れ線は2px、点は8px以上。
* 目盛りの線は`--chart-grid`の1px、横の線だけ。軸の線は`--chart-axis`。
* 金額の縦軸は0から始める（DS-02）。例外は部品の指定と注記が要る。
* 数値のラベルは、最新の期と、注目する値にだけ付ける（すべての棒に付けない）。
* 文字は本文の書体、`--text-small`以上、文字の色は`--color-text-muted`（系列の色を文字に使わない）。
* 増減は「＋」「−」と矢印を添える。色だけで示さない。

### 10.3 グラフの部品に必ず渡すもの
タイトル、単位、期間、出典と確認日、系列の名前、表で見るための同じ数値（DS-02、CLAUDE.md 9章）。

### 10.4 操作
* ビルドのときにSVGとして作る（要件定義書FR-301）。年次／半期、指標の切り替えは、作っておいたグラフを切り替える。
* 数値は、棒や点を選ぶ（タップ、クリック、キーボード）と、その近くに出す。マウスを重ねたときだけに出る情報にしない。どの数値も「表で見る」で読める。

## 11. 状態と操作

| 状態 | 見た目 |
| :--- | :--- |
| フォーカス（キーボード） | `--border-width-focus`の`--color-focus`の枠、要素から`--focus-offset`離す。すべての操作できる要素に付ける |
| ポインターを重ねた | リンクとボタンは`--color-primary-hover`。表の行は背景`--color-surface-sunken` |
| 押した | ポインターを重ねたときと同じ |
| 選んでいる | 背景`--color-primary-tint`、文字は太字 |
| 使えない | 文字`--color-text-muted`、枠は破線。理由を近くに書く |
| 開閉 | 開閉の記号を90度回す。動きは0.15秒以内。端末の「視差効果を減らす」では動かさない |

* 押せる範囲は一辺44px以上（DS-07）。小さく見える部品は、見た目より広い範囲を押せるようにする。
* マウスを重ねたときだけに出る情報を作らない。
