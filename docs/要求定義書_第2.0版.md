## 1. 概要

### 1.1 目的
日本国内の半導体業界に関する企業情報、工程・技術解説、業績、ニュースを分かりやすく提供する一般公開のWebサイトを構築する。本サイトの目的は、閲覧者に価値を届けること、運営を通じて運営者自身が半導体業界を深く学ぶこと、日本の半導体業界で活躍する人材の育成に情報で貢献することの3つとし、収益より優先する。

サイト名は「SemiCompass（セミコンパス）」とする。半導体（Semiconductor）と羅針盤（Compass）を組み合わせた名前で、業界の動向を示し、学ぶ人に道筋を示し、就職活動の進路選びを助ける、というサイトの役割を表す。名前に添える説明の一文は「日本の半導体業界を、企業・工程・ニュースでつなげて理解する」を案とし、トップページの最初の画面で、サイトが何であるかを伝えるために使う（UI-16）。

広告収入は、運営を続けるための手段と位置づける。当面の目安は、システムの運営費（NF-06）を賄える水準とする。
そのための価値の中心は、閲覧者の問いに素早く正確に答えることに置く。収益はその結果として得るものとし、収益と閲覧者の価値が衝突する場合の判断は1.8.3の原則に従う。
半導体業界に特化したサイトはページビューの規模に限度がある一方、読者が技術者・業界関係者・投資家であるため、広告単価を高くできる余地が大きい。そこで、収益を得る方法としては「量で稼ぐ」より「読者の質で稼ぐ」ことを基本とし、一定のページビューを確保した後は、広告単価の向上に重点を移す（1.4を参照）。

以下の指標を用い、段階ごとの目標値を定める（10章の未決事項を参照）。第1段階ではメールマガジン登録者数を最重要指標とする。

| Xでの言及・引用の数 | Xで本サイトやその図表が言及・引用された数。業界内での注目度を示す |

**1.2.1 重点指標**
1人で追える数に絞るため、毎月必ず確認する重点指標を次の3つとする。集客、継続、価値の3つの面を、1つずつの指標で押さえる。その他のKPIと価値指標（1.8.2）は参考指標とし、3か月に1回まとめて確認する。広告収益と費用は、事業の状態として別に毎月確認する（OP-07、AD-302）。

| 重点指標 | 押さえる面 | 理由 |
| :--- | :--- | :--- |
| メールマガジン登録者数 | 継続 | 第1段階の最重要指標。検索に依存せず、繰り返し訪れる読者の基盤を示す |
| 月間の訪問者数（UU） | 集客 | 検索などからの集客がうまくいっているかを示す |
| 疑問の解決率（VM-01） | 価値 | 閲覧者の問いに答えられているかを示す |

### 1.4 事業戦略と段階
サイトは次の3段階で成長させる。3章以降の要求の「段階」は、この区分を指す。

| 段階 | 期間の目安 | 目標 | 主な収益源 | 重点施策 |
| :--- | :--- | :--- | :--- | :--- |
| 第1段階：集客の土台づくり | MVP公開〜正式公開後1年目 | 検索流入の安定と、メールマガジン読者の獲得 | アドネットワーク（広告量は控えめ）、参考書のアフィリエイト | ページの自動生成によるロングテール集客、独自データの整備、メールマガジン登録導線 |
| 第2段階：広告単価の向上 | 1〜2年目 | 媒体価値を高め、直接販売の広告を始める | 純広告、メールマガジン広告、転職サービスの成果報酬型広告 | 媒体資料の作成、広告営業、決算期以外の特集による季節変動の平準化、論考の掲載（専門性の提示） |
| 第3段階：収益の多角化 | 2年目以降 | 収益源を増やし、継続利用を深める | タイアップ記事、特集スポンサー | ログイン機能（ウォッチリスト・通知）、中立性の維持 |

第1段階は、さらに「MVP」「正式公開」「公開後」の3つに分けて進める（1.12）。第2段階以降の期間の目安は、正式公開の時点から数える。

### 1.5 差別化方針
業績情報や技術ニュースの個別分野には、既存の有力サイトが存在する。本サイトは同じ土俵で競うのではなく、「サプライチェーン構造 × 業績 × ニュース」を半導体に絞ってつなげ、あるニュースがサプライチェーンのどこに影響し、関係企業の業績がどうなっているかを1か所で追える体験で差別化する。サプライチェーンマップ、工場・拠点マップ、IR重要ポイントなどの独自に編集したデータに、開発と運用の資源を重点的に配分する。

### 1.7 運営体制と制約
本サイトは運営者1名で、開発、編集、公開前レビュー、広告管理のすべてを担う。そのため、次の制約を他の要求より優先する。制約を満たせない要求は、段階または優先度を見直す。

| 制約 | 内容 |
| :--- | :--- |
| 運営体制 | 運営者1名。作業を分担する前提の要求（担当の分離など）は、方針の明文化など1人で実行できる形に置き換える |
| 運営費 | システムの運営費（人件費を除く）は、目安として月額5,000円以内に収める。AIの利用が増えた月に限り、上限を約10,200円（AIの上限10,000円＋その他約200円）とする。為替は1ドル150円と仮定し、大きく変動した場合は見直す。無料枠や定額のサービスを優先し、従量課金のサービスには上限を設定する |
| 運営作業の時間 | 平常時は週4.5時間（平日1日30分、土曜日2時間）、決算集中期（年4回、各3〜4週間。時期は運用ルール書で定める）は週10時間とする。MVP公開前の開発と初期データ作成には週10時間、正式公開後の開発には運営とは別に週3時間を使う。MVP公開から正式公開までの間の時間は、10章の未決事項16で決める |
| ニュースの件数 | ニュースは平日のみ公開する。1日1〜3件（上限3件。MVPの間は1〜2件。3章の冒頭）から始め、作業時間の実績（1.7.1、OP-09）で余裕を確かめたうえで、上限5件まで増やせる。レビューの作業量とAIの利用額を抑えるため |

年間の作業量の一覧と、作業が確保できる時間に収まらないときに後に回す順番は、運用ルール書で定める（OP-09、OP-10）。ただし、IR重要ポイントの公開期限（NF-09）、誤りの訂正、掲載企業からの連絡への対応（OP-08）、法令に関わる対応は後回しにしない。

**1.7.1 作業時間の試算（暫定）**
作業量は、週の合計ではなく、作業が最も集中する日・週で確かめる。次の試算は1件あたりの時間を仮定したものであり、MVPの運営期間に実績を測って見直す（1.12）。

| 場面 | 仮定 | 必要な時間 | 確保できる時間 | 判断 |
| :--- | :--- | :--- | :--- | :--- |
| 平日のニュース | 1件10分（候補の選択、解説のレビュー、事実確認の警告の判断、Xの投稿文の確認）。日次ブリーフの確認5分 | 1日2件で約25分、3件で約35分 | 1日30分 | 2件なら収まる。3件は超えやすく、5件は収まらない |
| 決算集中期のIR重要ポイント | 1社20分（下書きのレビュー、事実確認の結果の確認）。50社のうち約15社が同じ週に発表すると仮定 | 約5時間／週（ニュースを1日2件に減らす（CT-06）と合計約7時間） | 週10時間 | 5営業日の期限なら収まる。3営業日の期限では、発表が集中する日の翌日以降に1日2時間近くが必要になり、収まらない |
| 週次の作業 | メールマガジンの確認30分、誤り報告・問い合わせ30分 | 約1時間 | 土曜日2時間 | 収まる。月次のまとめ（FR-506）などは月1回、土曜日に割り当てる |

この試算にもとづき、ニュースの件数（1.7）とIR重要ポイントの公開期限（NF-09）を定める。

### 1.8 閲覧者に提供する価値
本サイトの価値を、ターゲットごとの「答えるべき問い」として定義する。3章以降の機能要求は、どの問いに答えるためのものかで紐づける。どの問いにも紐づかない機能は、価値を生んでいない可能性があるものとして見直しの対象とする。

### 2.1 対象範囲

| 区分 | 扱い | 企業ページ |
| :--- | :--- | :--- |
| 国内の上場半導体関連企業 | 全機能の対象 | あり |

### 2.2 区分ごとの表示方針
* 外資系の日本法人は非上場子会社であることが多く、EDINETから業績を取得できない。そのため、親会社の業績（海外の開示システムから取得）と、国内拠点の情報（所在地、投資額、補助金額、生産品目、稼働時期）を組み合わせて表示する。
* 総合メーカーは、全社の業績と半導体関連セグメントの業績を明確に分けて表示し、全社売上に占める半導体関連の比率を示す。
* 非上場企業・スタートアップは、ニュースの企業タグとして認識する。将来企業ページを追加できる構造にしておく。
* 株価および株価に連動する指標（PER・PBR、株価指数など）は掲載しない。投資判断層には、業績とIR情報の重要ポイントで価値を提供する。
* 掲載企業は100社程度とする。選定の基準は、半導体関連（設計、前工程、後工程、材料、装置、デバイス、検査）の売上が全社売上の一定割合（目安30%）以上の国内上場企業、半導体関連の比率が低くても世界シェア上位の製品を持つ総合メーカー、国内に主要な生産拠点を持つ外資系日本法人とする。比率の目安は、社数が100社程度に収まるよう企業リストの作成時に調整する。内容を詳しく載せる「詳細掲載」は、MVPの公開時に20社、正式公開時に50社とし、その後も順次増やす。詳細掲載でない企業は、企業名、証券コード、企業区分、工程・プロダクトの分類だけを載せ、内容は「Coming Soon」と表示して、順次、詳細掲載に切り替える（FR-108、FR-109）。
* 選考情報（エントリーシートの設問、面接の内容）、社員の口コミ、有価証券報告書で開示されていない働く環境の情報（残業時間、離職率など）は扱わない。一次資料で確認できず、正確性（NF-08）を保てないため。就職四季報など他社媒体の情報も転載しない。
* 海外の出来事（海外企業の投資、各国の規制など）は、日本企業への影響の観点で扱う。
* 商社・ユーザー企業は対象外とするが、車載やAIサーバー向けなどの需要側の動向は、業界動向・投資判断の重要情報として扱う。

| 従業員・人的資本・研究開発費・設備投資 | EDINET API（XBRL） | 完全自動 | 有価証券報告書の記載のみを使う。提出会社単体か連結かを区別して保存する |

| 市場統計 | WSTS、SEAJ等の公開資料 | 半自動 | 資料の形式変更を監視する |

### 5.3 比較可能性
* 決算期（3月期、12月期など）が異なる企業を比較する際は、期間のずれを注記する。業績は年次・半期で表示する（FR-301）。
* 会計基準（日本基準、IFRS、米国基準）の違いを企業ページと比較表に注記する。
* セグメントの横並び比較は、セグメント対応表に基づく参考値であることを明示する。

### 5.4 品質管理
* データ取得の失敗や、前期比の急変などの異常値を自動で検知する。
* 誤りが見つかった場合は、6.10の区分と期限に従って訂正し、訂正の記録を公開する。
* AI要約・解説の誤りを訂正する手順を定める。
* ユーザーが誤りを報告できる窓口を設ける。

## 6. 運営者要求

### 6.10 誤りの訂正

| NF-09 | 鮮度 | 有価証券報告書の提出から翌朝までに業績を反映する。決算発表からIR重要ポイントの公開まで5営業日以内とする（1人運営と1.7.1の試算を踏まえた暫定値。MVPの実績で見直す）。発表が集中する週は、投資判断層の関心が高い企業から順に公開し、その順番は運用ルール書で定める |
| NF-10 | 網羅性 | 詳細掲載の企業のページで、必須項目（事業概要、工程上の位置づけ、業績、IR重要ポイント）がすべて埋まっている割合を100%とする。外資系日本法人は、業績とIR重要ポイントに代えて、国内拠点の情報（FR-105の簡略化した扱い）を必須項目とする。Coming Soonの企業は、基本情報（企業名、証券コード、企業区分、工程・プロダクトの分類）が埋まっていることを条件とする |
| NF-11 | わかりやすさ | 解説文中の専門用語は、すべて用語集にリンクされている。かんたん解説は、用語集を開かなくても読める |
| NF-12 | 信頼性 | すべての数値に出典と日付を表示する |
| NF-13 | 変更の品質 | すべての変更（AIやClaudeへの指示で作った変更、運営者の変更、定期処理のプログラムの変更）は、取り込む前に自動で確認する。データの形式、必須の項目、表記のルールと禁止表現、プログラムの動作を確かめ、問題のある変更は取り込めないようにする |
| NF-14 | 公開の安全性 | 公開の直後に、主要なページが正しく表示されるかを自動で確認する。問題を検知したときは、直前の公開の状態に戻し、運営者に知らせる |

## 9. 計測・改善
* アクセス解析を導入し、1.2のKPIと、1.8.2の価値指標を分けて継続的に計測する。重点指標（1.2.1）は毎月、参考指標は3か月に1回確認する。
* 外部サイトからのリンク数とXでの言及・引用の数を月1回確認し、媒体資料（AD-203）の根拠として記録する。Xの言及はAPIの利用料を避けるため、運営者がXの検索で確認する。
* よく見られているページと離脱が多いページを分析し、導線や解説内容の改善に活かす。
* 検索キーワードごとの流入を分析し、不足しているページ（用語、テーマなど）を追加する。
* 広告の配置を変更した際は、収益とユーザー体験（回遊率、離脱率等）の両方への影響を確認する。
